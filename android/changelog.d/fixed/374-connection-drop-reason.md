- **The session log now says why a connection dropped** — when the frame loop ends by itself, the diagnostic export's session log gets one `LINK_END` line naming the reason (read timed out with no frame, the adapter closed the connection, Bluetooth disconnected with its GATT status, a Bluetooth link closed after an unacknowledged write, or a read error by its class name) and how many seconds nothing had arrived before it, so a key-off can be told from an adapter that closed the link. A stop by the user still writes only `LINK_STOP`; reconnects are unchanged (`LinkEnd`). ([#374](https://github.com/klexical/openRS_/issues/374))
