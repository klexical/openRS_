- **A Bluetooth firmware command's error could read as accepted** — the `AT+FRS` reply was read as accepted whenever its text held the letters "OK" anywhere, so an error whose reason contained them would have been logged and exported as ACCEPTED (no current firmware error does). The reply is now read by its status word after `+FRS:` alone: `OK` accepted, `BUSY` busy, `ERROR` failed, anything else an unexpected reply. (`can/FirmwareApi.kt`, `BleFirmwareApi`) ([#607](https://github.com/klexical/openRS_/issues/607))
